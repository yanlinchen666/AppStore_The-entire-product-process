## 四、首次启动流程

**步骤 1：准备 MySQL 数据库**

1. 启动 MySQL 8.0+ 服务
2. 创建数据库（utf8mb4 字符集）：

```sql
CREATE DATABASE appstore_vc CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

3. **建议**把 MySQL 的 `wait_timeout` 调到 28800（默认值），避免长 LLM 调用期间连接被服务端关闭。在 `my.ini` 中加：

```ini
[mysqld]
wait_timeout=28800
interactive_timeout=28800
```

> 即使不调，代码层也已经做了防护（每个 pipeline 阶段用独立短 session、连接池 `pool_recycle=60`、`pool_pre_ping=True`），但调大 wait_timeout 是更稳妥的选择。

**步骤 2：创建 conda 环境并安装后端依赖**

```powershell
conda create -n appstore_vc python=3.10 -y
conda activate appstore_vc

cd D:\AI\agent_vc\AppStore_vc\AppStore_vc\backend
pip install -r requirements.txt
```

**步骤 3：配置环境变量**

```powershell
cd D:\AI\agent_vc\AppStore_vc\AppStore_vc\backend
Copy-Item .env.example .env
```

编辑 `.env`，**至少填这两个**：

```env
SILICONFLOW_API_KEY=sk-你的SiliconFlow密钥
SILICONFLOW_LLM_MODEL=Qwen/Qwen3-8B
EMBEDDING_MODEL=BAAI/bge-m3
SILICONFLOW_BASE_URL=https://api.siliconflow.cn/v1

# 数据库（默认 root/root，按实际改）
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root
DB_PASSWORD=你的MySQL密码
DB_NAME=你的数据库名称

# Neo4j（可选；不填则图功能自动禁用，不影响主流程）
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=你的Neo4j密码
```

如果本机走了代理访问 SiliconFlow，还需要：

```env
HTTP_PROXY=http://127.0.0.1:7897
HTTPS_PROXY=http://127.0.0.1:7897
NO_PROXY=127.0.0.1,localhost,::1
```

## 六、使用流程

### 1. 通过前端界面

1. 打开 http://localhost:5173
2. 侧边栏点「创建分析」
3. 输入 App Store 链接，例如：
   ```
   https://apps.apple.com/us/app/workout-for-women-home-gym/id839285684
   ```
4. 填写分析目标，例如：`分析订阅问题和功能可用性`
5. 调整评论数量（建议初次用 50 测试，正式分析用 100+）
6. 点击「开始分析」→ 自动跳转到 RunDetail 页面
7. ProgressTracker 每 1.5s 轮询进度，9 个阶段依次完成
8. 完成后切到「发现 / PRD / 测试用例」标签查看结果

### 2. 通过 API（PowerShell ）

```powershell
# 启动分析
Invoke-RestMethod -Uri "http://localhost:8000/api/analyze" -Method POST `
  -ContentType "application/json" `
  -Body '{"app_url":"https://apps.apple.com/us/app/workout-for-women-home-gym/id839285684","analysis_goal":"订阅问题","max_reviews":50}'

# 查看所有任务
Invoke-RestMethod "http://localhost:8000/api/runs"

# 查看某个任务详情
Invoke-RestMethod "http://localhost:8000/api/runs/1"

# 查看进度
Invoke-RestMethod "http://localhost:8000/api/analyze/1/progress"
```

## 七、维护脚本

| 脚本 | 作用 | 命令 |
|------|------|------|
| `app.create_tables` | 创建所有数据表（幂等） | `python -m app.create_tables` |
| `app.migrate_schema` | 增量字段迁移（幂等） | `python -m app.migrate_schema` |
| `app.cleanup_zombies` | 清理僵尸分析任务 | `python -m app.cleanup_zombies`（dry-run）<br>`python -m app.cleanup_zombies --apply`（实际删除） |

> **僵尸任务**：如果后端在分析过程中被重启（uvicorn `--reload` 触发、手动 Ctrl+C 等），后台 pipeline 线程死亡，但数据库里的 `status="running"` 不会被更新，前端会看到进度永远 0%。
> - 后端启动时会自动把这些任务标记为 `failed`
> - 如果想直接删掉（保留 reviews 数据），用 `cleanup_zombies --apply`

## 八、常见问题

1. **前端进度条卡在 0% 不动**

**原因**：后端重启过，那个 run 是僵尸任务（DB 显示 running 但实际 pipeline 已死）。

**解决**：
- 后端启动恢复机制已经自动把僵尸任务标记为 `failed`，刷新前端即可看到
- 想彻底删除：`python -m app.cleanup_zombies --apply`
- 想重新分析：创建新的分析任务即可（reviews 数据保留，会跳过已采集的）

**2. 分析报错：`MySQL Connection not available`**

**原因**：MySQL 的 `wait_timeout=120s`，pipeline 在调 LLM 期间持有的 DB 连接被服务端关闭。

**解决**（任选其一）：

- **代码层已修复**：每个 pipeline 阶段用独立短 session，LLM 调用期间不持有 DB 连接；连接池 `pool_recycle=60` + `pool_pre_ping=True` 双保险。如果你跑的是最新代码，应该不会再出现这个错误
- **MySQL 层加保险**：把 `wait_timeout` 调到 28800（见步骤 1）

**3.后端启动报 `ModuleNotFoundError**

**解决**：忘记激活 conda 环境或没装依赖。

```powershell
conda activate appstore_vc
cd D:\AI\agent_vc\AppStore_vc\AppStore_vc\backend
pip install -r requirements.txt
```

**4. 后端启动报 Neo4j 连接失败**

**现象**：日志里看到 `Failed to connect to Neo4j ... Graph features will be disabled.`

**说明**：这是警告不是错误，Neo4j 没配置好时图功能自动禁用，不影响主流程（采集 / 分析 / PRD / 测试用例都正常）。

**解决（可选）**：在 `.env` 里填正确的 `NEO4J_PASSWORD`，或本地启动 Neo4j Community 服务。

**5. 数据库连接失败**

**排查**：
1. MySQL 服务是否启动（`Get-Service mysql*` 或服务管理器查看）
2. `.env` 里 `DB_HOST/DB_PORT/DB_USER/DB_PASSWORD/DB_NAME` 是否正确
3. 数据库 `appstore_vc` 是否已创建
4. 用以下命令快速验证连接：
   ```powershell
   conda activate appstore_vc
   python -c "from app.database import SessionLocal; db=SessionLocal(); print(db.execute(__import__('sqlalchemy').text('SELECT 1')).scalar()); db.close()"
   ```

**6.LLM API 调用失败**

**排查**：
1. `.env` 里 `SILICONFLOW_API_KEY` 是否正确
2. 网络是否能访问 `https://api.siliconflow.cn`（需要代理的话配 `HTTP_PROXY/HTTPS_PROXY`）
3. 后端控制台日志会打印具体错误
